# Data saving (DataStore wrappers, session locks, templates)

How the games load, hold and save player data. You will find three families here: hand-rolled
DataStore services (plain GetAsync/SetAsync up to proper UpdateAsync session leases), thin
game-side layers on top of ProfileService / ProfileStore (the libraries themselves are in
`Scripts/Libraries/`), and one classic community module (Stravant's PlayerDataStore). Read the
aura-ascension file first: it is the cleanest complete example. Then look at `_patterns/` for a
cleaned-up, dependency-free version that combines the best ideas from all of them.

## Techniques seen across games

- **Never play on default data after a failed load and then save it.** The good games kick (`steal-a-brainrot`, `rcu-roller`) or keep an unsaved in-memory profile (`aura-ascension`, `rivals-modded`). `steal-an-egg` shows the bug: a template profile that later overwrites the real save.
- **Session locks** come in three strengths: a flag in the save (`big-paintball` PlayingSession), a separate lock store with a timeout (`steal-a-brainrot`, `uno`), and a lease stored in the save and checked inside the same `UpdateAsync` (`aura-ascension`, ProfileStore). Only the last is atomic.
- **Reconcile on every load** so new template fields appear for old players. Deep reconcile (`rcu-roller`, `steal-an-egg`) handles nested tables; build the template in a function (`rivals-modded` DataTemplate.New) so players never share a table.
- **Clean up stale content on load**: `drill-and-mine` drops inventory ids that no longer exist in the config; `evade`/`steal-a-brainrot` reset 'Reserved'/'IsFake' podium slots that only make sense in one session.
- **Save less, save smarter**: only dirty players in autosave (`steal-an-egg`, `aura-ascension`), a debounced ScheduleSave after important changes (`drill-and-mine`), and parallel saves in `BindToClose` with a ~25 second deadline.
- **Freeze saves during trades** (`uno` SaveLocked) or save immediately after a purchase so a crash cannot roll back one side of a deal.

## Things we did not copy (and why)

- `murder-mystery-2` and `murderers-vs-sheriffs` DataModule files mix saving with Discord webhooks / outside HTTP calls, so they were left out.
- `bee-swarm-sim` DataStore2 loads a module by asset id (`require(1936396537)`); not copied. DataStore2, ProfileService and ProfileStore themselves are already in `Scripts/Libraries/`.
- `steal-an-egg-admin` contains saveinstance-decompiled modules (and HIGH scanner flags), so nothing from that game was copied here.
- `big-paintball` MockDataStoreService files are the public MockDataStoreService library, not game code.
