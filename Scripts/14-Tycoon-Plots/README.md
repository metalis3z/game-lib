# 14 - Tycoon & Plots

Scripts for games where each player owns a piece of the map: handing out plots, classic tycoon buttons, droppers, upgraders and collectors, base upgrades (extra floors), conveyor belts that deliver items to your base, placing things on a plot, and the "steal-a-X" loop (walk into someone's base, grab an item, carry it home while they try to stop you, lock your base for a minute). Most of the steal code comes from the Steal a Brainrot family (steal-a-brainrot, steal-a-brainrot-sab-files, evade, which is a re-skin of the same codebase) and steal-an-egg. The classic tycoon pieces come from advanced-warfare-tycoon (berezaa's tycoon kit) and scp-tycoon. Every file is a reference copy with its original path in the header. Bundled files join several tiny scripts, each copied whole. Excerpt files list the original line ranges. The `_patterns` folder has four clean modules written from these ideas, ready to drop into a new game.

Several useful scripts were skipped because they are decompiler output: the grow-a-garden-2 placement and steal controllers, the steal-an-egg client modules, and every `PlotClient` / `PlotController` client file in the brainrot games.

## Techniques seen across games

- **The item stays with the victim until delivery.** Steal a Brainrot and evade flag the victim's podium (`AnimalList[i].Steal = thiefUserId`) and only move the data in `CompleteSteal`. Death, leaving or ragdolling calls `CancelSteal`, which just clears the flag. Nothing can be duplicated or lost mid-carry. The trade-off is that flags can get stuck, so steal-a-brainrot runs a janitor loop every 10s.
- **Steal validation is a zone test on the server.** Every steal remote recomputes "is the thief's HumanoidRootPart inside the victim plot's `StealHitbox`?" with `GetPartBoundsInBox` or a `PointToObjectSpace` box test. Delivery uses the same test against the thief's own `DeliveryHitbox` on Heartbeat (steal-an-egg uses a dot product against a separation line). None of them trust a client "I delivered it" event.
- **Base locks: a server timer and a client barrier.** `LockBase` writes `BlockEndTime` (server time + 60s + rebirth bonus) to the replicated plot state and shows laser parts. Players already inside get "grandfathered" so they can still finish. In the leaked servers, the Steal remote never checks `BlockEndTime`; only the client-side lasers block thieves. A real game should check it on the server, as `_patterns/StealSystem.lua` does.
- **Plots are found by an owner attribute, not by name.** drill-and-mine, steal-an-egg and brainrot-lab sort `workspace.Plots` by the number in the name, take the first one without `OwnerUserId`, and teleport the player on every `CharacterAdded`. The brainrot games also rename the plot to a GUID and keep a `_G.playerPlots[userId]` lookup. A module-level table (like `PlotManager.GetPlot`) is cleaner.
- **Classic tycoons stash the purchases and clone them back.** berezaa's kit clones every `Purchases` child into a table at start and deletes it from the world. Buying parents the clone back, and `Dependency` values reveal the next button. Modern games keep the purchased item names in save data and rebuild from templates. drill-and-mine's base upgrades and `_patterns/TycoonKit.lua` work this way.
- **Idle income is computed from timestamps, not ticked.** evade's `ClaimCoins` pays `(now - LastCollect) x generation x multiplier`, plus any stored `OfflineGain`, and then resets `LastCollect`. Stolen items get `LastCollect = now`, so a thief can't cash out the victim's backlog.
